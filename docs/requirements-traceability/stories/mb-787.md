# MB-787 — PayOS specialist bank payout

## Backend implementation (2026-11-04)

Approved authority is the accepted [ADR 0047 payout amendment](../../adr/0047-payos-active-gateway-momo-dormant.md#mb-787-payout-amendment-2026-11-04), decision `MB-PAYOS-PAYOUT-001`. It supersedes the missing-channel and sole-MoMo payout clauses while preserving VND economics, dispute eligibility, seven-day hold, 100,000 VND minimum, one logical request per server day, immutable allocation/70% share and non-redeemable fixture provenance. Production remains blocked.

Consultation OpenAPI 1.21.0 adds current pending/confirmed masked bank revisions, independently gated PAYOS readiness, backend bank-list proxy, audited ADMIN exact account inspection and versioned manual confirmation, provider-affine payout evidence/scheduling and explicit FAILED-only ADMIN retry. Specialist command replay observes the original result. A matched authenticated child transaction proves payment; outer batch approval does not. At 24 hours unresolved funds remain reserved with UNKNOWN/NEEDS_REVIEW. Previously linked failed-payout earnings are reported as retryPendingVnd and excluded from new withdrawals.

Provider contract is frozen in `contracts/openapi/consultation-service-v1.yaml` before the parallel web consumer. Claude synchronizes from this story's backend worktree and owns web/BFF/UI/tests. Deployment requires additive owner migrations first, synchronized consumers and drained legacy writers before PAYOS enablement. Real PayOS interoperability and funded eligible earning QA belong to MB-788; deterministic local tests make no real provider or balance calls. Delivery/merge and live staging execution need their separate owner authorization.

The existing administration-audit fact gains four content-free event types: `consultation.payout-destination.inspected`, `consultation.payout-destination.confirmed`, `consultation.payout.retried` and `consultation.payout.closed`. They retain the `CONSULTATION`/`SPECIALIST_REVIEW` descriptor boundary and the account/tombstone target shape. Identity accepts these via its existing privacy allowlist; no bank fields or new audit domain are introduced.

Verification evidence and known limits are recorded in the external backend handoff. This record does not claim that the in-progress implementation or MB-788 live gates have completed.
