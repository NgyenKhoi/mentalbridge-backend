# MB-800 — live specialist inbox invalidations

Recorded: 2026-11-07. Backend provider for frontend MB-801, owned by ngocquyen.
The accepted transport boundary remains [ADR 0016](../../adr/0016-feature-scoped-kafka-and-opentelemetry.md)
and the [asynchronous messaging guide](../../agent-guides/async-messaging.md).
No new architecture decision or Consultation behavior change is required.

## Backend delivery boundary

Only newly materialized v2 specialist appointment notifications participate.
Content locks the role-scoped preference row and commits the eligible inbox row
and unique creation outbox pointer in the same local PostgreSQL transaction.
Its fenced relay rechecks current eligibility before Kafka publication. Realtime
validates the creation contract, publishes minimized routing metadata through
Redis, then forwards each matching SPECIALIST socket's existing Identity bearer
to Content for fresh owner authorization. It checks connection, principal and
original JWT expiry again after the read before emitting. No database
transaction spans broker, REST or socket I/O.

`DELIVERED` continues to mean durable inbox availability. Notification-state
`CANCELLED`, deleted/expired rows and disabled preferences suppress live delivery;
appointment status `CANCELLED` remains an eligible appointment fact. Content
does not scan, backfill or replay the 40 legacy payloads without specialist
identity. Native push, browser UI, shared data and deployed infrastructure remain
outside this backend implementation.

## Contracts and consumer

Content OpenAPI v1.12.0 adds the authenticated, non-cacheable, owner-scoped
`GET /internal/v1/notifications/{notificationId}/live-eligibility` projection.
Realtime OpenAPI v1.1.0 adds optional `specialistNotifications` readiness for the
enabled feature's Kafka consumer and Redis subscription.
Kafka creation v1.0 carries immutable creation identity and minimized routing;
retry v1 reuses that body with bounded attempt/not-before headers; the v1.0
dead-letter contract contains only a SHA-256 digest and safe diagnostics.

The numeric v1 socket schema is a separate `notification.created` event on the
existing authenticated `/realtime` namespace. It contains only notificationId
inside its payload and preserves the closed existing chat/ready event union.
MB-801 syncs/checks contracts after backend merge before implementing its
consumer, obtains fresh one-use credentials as needed, and refetches inbox plus
absolute unreadCount after `connection.ready`, reconnect and coalesced signals.
Client code never increments counts or restores event data directly.

## Acceptance and evidence

Required automated coverage includes atomic rollback/duplicates, fenced relay
claims and crash recovery, owner/foreign/role authorization, current preference
and row suppression, strict contracts, bounded retry and digest-only poison
handoff, multiple devices across two Realtime replicas, post-I/O credential
expiry, dependency loss and REST recovery. The local backend handoff records
exact commands, counts and any external gate blocker. Browser acceptance and
deployment remain later MB-801/owner-authorized work; service fixtures are not
authenticated browser end-to-end evidence.
